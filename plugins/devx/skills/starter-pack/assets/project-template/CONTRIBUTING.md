# Contributing

## Development Setup

See `README.md` for local setup.

## Before Starting

- Pick or create a tracked task.
- Read the related product and architecture documents.
- Create a branch from the current main branch.

## Branch Naming

- `feature/[short-name]`
- `fix/[short-name]`
- `chore/[short-name]`

## Commit Messages

Use short messages that describe the change. For example:

- `feat: add note creation`
- `fix: reject unauthorized access`
- `docs: update deployment steps`

## Pull Request

Include:

- What changed and why
- Tests run
- Screenshots for visible UI changes
- Migration notes where needed
- Known limits

## Review

Do not merge with required checks failing. Resolve review comments before merge and keep unrelated refactoring out of feature pull requests.
